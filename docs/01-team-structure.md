# AIエージェントチーム構成

「チーム」は人間の雇用ではなく、Claude Code のサブエージェント（役割ごとのプロンプト/タスク定義）で構成する。各エージェントは明確な入出力と権限範囲を持ち、資金・外部公開・契約に関わる行為は必ず人間承認を挟む。

## 体制図

```
                    ┌─────────────────────┐
                    │  オーケストレーター    │  ← あなた（人間）が方針を指示
                    │  (統括AI)            │     各エージェントへタスク分配・優先順位付け
                    └──────────┬───────────┘
         ┌───────────┬─────────┼─────────┬───────────┐
         ▼           ▼         ▼         ▼           ▼
   ┌─────────┐ ┌──────────┐ ┌───────┐ ┌────────┐ ┌──────────┐
   │リサーチAI │ │企画AI     │ │実行AI  │ │集客AI   │ │計測・経理AI│
   └─────────┘ └──────────┘ └───────┘ └────────┘ └──────────┘
```

## 各エージェントの役割

### 1. オーケストレーター（統括AI）
- **目的**: 全体の優先順位付け、各エージェントへのタスク割当、進捗のとりまとめ
- **入力**: 人間からの方針・目標（`docs/00-goal.md`）
- **出力**: 週次/月次サマリー、次のアクションプラン
- **人間承認が必要な場面**: 事業ドメインの最終確定、予算配分の変更

### 2. リサーチAI
- **目的**: 市場調査、競合分析、トレンド調査、収益モデルの事例収集
- **入力**: 調査対象ドメイン・キーワード
- **出力**: 調査レポート（`docs/research/` 配下に蓄積）
- **人間承認**: 不要（情報収集のみ）

### 3. 企画AI
- **目的**: リサーチ結果をもとに商品/サービス企画、価格設計、収益モデル設計
- **入力**: リサーチAIのレポート、`docs/02-domain-selection.md` の評価軸
- **出力**: 企画書、収益シミュレーション
- **人間承認**: 企画の実行GOサイン

### 4. 実行AI（制作・開発）
- **目的**: コンテンツ制作、プロダクト/自動化スクリプトの実装、リポジトリへの実装
- **入力**: 企画AIの承認済み企画
- **出力**: 実装物（コード、コンテンツ、成果物一式）
- **人間承認**: 外部への公開・デプロイ・支払いを伴う操作

### 5. 集客AI（マーケティング）
- **目的**: 集客チャネル設計、SNS/広告文面のドラフト作成、SEO/導線設計
- **入力**: 実行AIの成果物
- **出力**: 施策案、広告文・投稿文のドラフト
- **人間承認**: 実際の広告出稿・投稿・費用発生を伴う施策の実行

### 6. 計測・経理AI
- **目的**: `data/revenue.csv` への収益記録、`scripts/progress.py` による進捗レポート作成
- **入力**: 実績データ
- **出力**: 進捗レポート、目標乖離のアラート
- **人間承認**: 不要（記録・可視化のみ）。ただし数値の正確性は人間が定期確認する

## 運用ルール

1. **資金・契約・個人情報・外部アカウントに触れる操作は必ず人間承認を経る**
2. 各エージェントの成果物はこのリポジトリ配下に記録し、判断の根拠を追跡可能にする
3. 週次で `scripts/progress.py` を実行し、目標との乖離を確認する
4. ドメイン未確定の間は、リサーチAI・企画AIを中心に `docs/02-domain-selection.md` の候補を埋めていく
